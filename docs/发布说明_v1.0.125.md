# v1.0.125 发布说明：新客队列经营分析

## 结论

本版本把新客从“期间标签”扩展为可持续观察的客户队列。新客身份统一按系统最早承保时间判断，并可分别观察首现月、首现后12个月和首现当年度的再次承保、产品购买及期交贡献。

## 主要调整

- 客户分析新增“新客经营”页签和`/api/customer-analysis/new-customer-cohort`接口。
- 展示系统新客、可追踪新客、再次承保客户数及占比、再次承保保单数、人均再次承保次数、首张/再次承保期交、再次承保期交占比和观察完整率。
- 展示相对首现月份的再次承保节奏、各首现月份表现、分业务表现和产品购买明细。
- 年度、季度、月度用于选择新客首现队列；业务、机构、长险和产品用于筛选观察窗口内的业绩保单。
- 未满观察窗口的客户不剔除，但单列数量和完整率，避免把未成熟队列误判为完整12个月表现。

## 统计边界

- 系统新客以当前客户清单可追溯历史为准；接入公司统一客户主数据前，不表述为公司全量客户口径。
- 首现后12个月采用`[首次承保日, 首次承保日+12个月)`，满12个月当日不计入。
- 再次承保不含系统首张保单；同日多单也只把一张识别为首张。
- 产品、保费和再次承保仅覆盖已关联客户清单的OTO、证保、蚁桥业绩。

## 发布要求

- 生产已有全量库时使用`REBUILD_DATABASE=0 sudo bash deploy/deploy.sh`，不得用旧Excel覆盖生产运行库。
- 本版本不修改生产数据库结构，不需要重建客户事实或全量导入。
- 上线后验收新客队列接口、客户分析页面、鉴权、服务日志和SQLite完整性。
