# v1.0.124 发布说明：全量历史库查询提速

## 结论

本版本保留SQLite架构，针对全量历史业绩导入后主看板变慢的问题，消除队伍和产品分析的全表扫描及重复请求。业务指标定义、客户分析口径和生产数据不作调整。

## 主要调整

- 队伍结构与产能分析优先读取人员月度聚合，用户展开模块后才加载。
- 产品结构与前三产品优先读取产品日级聚合，支持原有年度、季度、月份、机构、业务模式和截至日筛选。
- 聚合尚未建立时，后端只读取所选年度和必要字段，不再一次性加载全部历史明细。
- 主看板复用已返回的产品数据，避免首屏重复请求同一接口。
- 聚合重建完成后更新SQLite查询规划统计。

## 验证基线

- 全量测试和生产验收结果以项目工作日志为准。
- 5175228行业绩副本完成20个年度聚合重建；`integrity_check`与`quick_check`均为`ok`。
- 本地大库实测：产品查询约9—13毫秒；队伍单月约64毫秒、年度热查询约141—151毫秒。

## 发布要求

- 生产部署前必须使用SQLite Online Backup形成可恢复备份。
- 生产已有全量库时使用`REBUILD_DATABASE=0 sudo bash deploy/deploy.sh`，部署脚本仍会按年度重建聚合，不会用服务器旧Excel覆盖运行库。
- 全量聚合重建实测约6分钟，部署期间应停止主服务并预留维护窗口。
