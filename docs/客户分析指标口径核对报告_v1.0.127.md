# 客户分析指标口径核对报告（v1.0.127）

## 一、报告用途

本报告用于核对客户分析模块当前已经执行的统计口径。页面结论以本报告和项目数据字典为准；后续如调整定义，应同时修改查询逻辑、页面说明、测试和数据字典。

当前模块回答四类问题：

1. OTO、证保、蚁桥在所选期间服务了多少客户、承保多少保单、贡献多少期交保费；
2. 这些业绩分别由系统新客、系统老客和未关联客户贡献多少；
3. 新客首次出现后，在首现月、首现后12个月或首现当年度又承保几次、购买什么产品、贡献多少期交保费；
4. 期间客户累计持有多少保单、当前有多少有效保单、首次复购间隔多久，以及期间业绩保单当前处于何种状态。

> 重要边界：本模块的“系统”是当前客户清单与历史业绩可覆盖的系统范围，不等同于太平人寿公司级统一客户主数据。当前保单状态是客户清单数据截止日的快照，不是13个月或25个月继续率。

## 二、数据来源与主键

| 数据层 | 当前来源 | 主键/去重键 | 用途 |
|---|---|---|---|
| 历史业绩明细 | OTO、证保、蚁桥业绩基表 | 业绩聚合后以“年月+业务+机构+投保单号”唯一 | 期交、年化规保、折算保费、价值保费、承保件数、业务、机构、长短险、产品 |
| 客户保单快照 | 客户清单CSV/XLSX | 投保单号 | 客户归属、承保时间、当前保单状态、终止原因、状态截止时间 |
| 客户主表 | 从客户保单快照计算 | 投保人id | 客户首张保单、首次承保时间、累计持单数和当前状态数量 |
| 客户月度事实 | 历史业绩与客户保单快照关联 | 年月+业务+机构+投保单号 | 页面查询、新老客划分、客户贡献、状态和匹配率 |
| 产品画像 | 历史业绩明细 | 投保单号 | 新客观察窗口内的产品名称和产品类型 |

当前客户唯一标识使用源数据中的“投保人id”。同一自然人如在源系统中存在多个投保人id，当前会被识别为多个客户；不同自然人如错误共用同一投保人id，当前会被识别为同一客户。系统不根据姓名、手机号或证件号码自行合并客户。

同一投保单号出现多条客户记录时，导入阶段归并为一份保单快照；同一保单不得对应不同投保人id。网页增量导入发现此类冲突时整批阻断，不静默改写客户归属。

## 三、时间边界

### 3.1 统计期间

| 选择项 | 起始日 | 结束日 |
|---|---|---|
| 年度累计 | 1月1日 | 12月31日与数据截止日两者较早者 |
| 季度 | 自然季度首日 | 自然季度末日与数据截止日两者较早者 |
| 月度 | 自然月首日 | 自然月末日与数据截止日两者较早者 |

历史年度默认按完整自然期观察；数据截止年度按客户清单最新有效快照日截断。若所选期间尚未到达数据截止日，页面不计算该期间。

### 3.2 三个“时间”不能混用

| 时间 | 用途 |
|---|---|
| 业绩年月/交易日期 | 决定一张业绩保单进入哪个经营统计期间 |
| 客户首次承保日期 | 决定客户是新客还是老客、属于哪个首现队列 |
| 客户清单导入时间 | 决定保单状态快照的新旧及页面“状态截至”日期 |

## 四、筛选器作用范围

| 筛选器 | 经营概览、新老客户 | 持单与间隔 | 保单状态 | 新客经营 |
|---|---|---|---|---|
| 年份/季度/月度 | 限定期间业绩 | 先选出期间有业绩的客户，再看其全部已知保单 | 限定期间业绩保单 | 决定“首次出现在哪个期间”的新客队列 |
| 业务 | 限定OTO/证保/蚁桥业绩 | 先按业务选客户，持单仍看该客户全部已知保单 | 限定该业务的期间业绩保单 | 限定观察窗口内的业绩保单，不改变新客身份 |
| 机构 | 限定业绩机构 | 先按机构选客户，持单仍看该客户全部已知保单 | 限定该机构的期间业绩保单 | 限定观察窗口内的业绩保单，不改变新客身份 |
| 全部/长险 | 限定期间业绩保单 | 先按保单范围选客户，持单仍看其全部已知保单 | 限定展示的期间业绩保单 | 限定观察窗口内的业绩保单，不改变新客身份 |
| 产品 | 不适用 | 不适用 | 不适用 | 限定观察窗口内的产品业绩，不改变新客身份 |
| 观察窗口 | 不适用 | 不适用 | 不适用 | 决定新客首现后跟踪到何时 |

客户可能跨业务、跨机构购买。因此分业务客户数、分机构客户数不能直接相加作为整体客户数；整体客户数始终按投保人id去重。

## 五、新客、老客和未关联客户

### 5.1 期间新客

定义：客户在当前系统覆盖历史中的最早承保日期落在所选期间，并且该客户在所选期间内产生了已关联的OTO、证保或蚁桥业绩。

公式：

`期间新客数 = COUNT(DISTINCT 投保人id)，条件：首次承保日∈[期间开始日, 期间结束日]`

注意事项：

- 新客身份由客户全历史最早承保日期决定，不由首次进入某业务、某机构或某产品的日期决定；
- 客户第一次在OTO承保、之后首次在证保承保，证保视图中仍是系统老客，不是“证保新客”；
- 只有客户清单已关联的保单可以识别新客；未关联业绩不强行归类。

### 5.2 期间老客

定义：客户最早承保日期早于所选期间开始日，并且该客户在所选期间内产生了已关联的OTO、证保或蚁桥业绩。

公式：

`期间老客数 = COUNT(DISTINCT 投保人id)，条件：首次承保日 < 期间开始日`

### 5.3 未关联客户业绩

定义：业绩保单未能按投保单号关联到客户保单快照，因而无法确认投保人id或客户首次承保时间。

处理规则：

- 保单、期交保费和状态均保留；
- 不计入新客或老客；
- 单列“未关联期交”和匹配率；
- 不以0、不以推测客户、不以业绩表中不稳定字段强制补齐。

## 六、经营概览指标

| 指标 | 分子/算法 | 分母 | 补充说明 |
|---|---|---|---|
| 客户数 | 所选业绩范围内投保人id去重数 | 无 | 未关联保单的空客户不计入客户数 |
| 保单数 | 所选业绩范围内投保单号去重数 | 无 | 同一保单多条业绩行只计1份 |
| 期交保费 | 所选范围期交保费求和÷10000 | 无 | 单位万元，保留原始正负冲正 |
| 新客数 | 按5.1定义去重客户数 | 无 | 固定期间口径 |
| 老客数 | 按5.2定义去重客户数 | 无 | 固定期间口径 |
| 新客期交 | 新客保单期交保费求和÷10000 | 无 | 单位万元 |
| 老客期交 | 老客保单期交保费求和÷10000 | 无 | 单位万元 |
| 未关联期交 | 无法识别新老客的保单期交求和÷10000 | 无 | 单位万元 |
| 新客业绩占比 | 新客期交 | 新客期交+老客期交 | 未关联期交不进入分母；分母为0时显示“--” |
| 老客业绩占比 | 老客期交 | 新客期交+老客期交 | 与新客占比勾稽为100%；分母为0时显示“--” |
| 当前有效保单 | 所选期间业绩保单中，当前状态组为“有效”的保单数 | 无 | 状态取客户清单最新快照 |
| 当前有效率 | 当前有效保单数 | 所选期间业绩保单总数 | 分母包含未关联保单；分母为0时显示“--” |
| 退保保单 | 所选期间业绩保单中，终止原因为“退保终止”的保单数 | 无 | 不含契撤、到期、满期和理赔 |
| 退保率 | 退保保单数 | 所选期间业绩保单总数 | 是截至快照日的累计状态占比，不是年度发生率 |
| 犹豫期撤保保单 | 终止原因为“契撤终止”，或犹豫期退保时间非空的保单数 | 无 | 与退保分开 |
| 保单匹配率 | 已关联客户快照的期间业绩保单数 | 期间业绩保单总数 | 按投保单号去重 |
| 保费匹配率 | 已关联保单期交绝对值之和 | 全部保单期交绝对值之和 | 使用绝对值，避免正负冲正相互抵消；分母为0时显示“--” |

月度新客、老客趋势按每个自然月重新判断：客户首次承保年月等于该月为当月新客，早于该月为当月老客。年度新客数不等于12个月新客数机械相加时的跨月重复问题：客户只会在其首次出现月成为一次月度新客，但老客可以在多个后续月份重复出现。

## 七、新客首现队列与后续经营

### 7.1 新客队列

“系统新客数”指首次承保日落在所选年度、季度或月份的全部客户，不要求其观察窗口内一定有符合业务、机构、长险或产品筛选的业绩。

“可追踪新客数”指上述系统新客中，在所选观察窗口内至少有一份符合当前业务、机构、长险和产品筛选的已关联业绩保单的客户。

`追踪率 = 可追踪新客数 ÷ 系统新客数`

### 7.2 观察窗口

| 窗口 | 起点 | 自然终点 | 是否包含终点 |
|---|---|---|---|
| 首现月 | 客户首次承保日 | 该自然月最后一日 | 包含 |
| 首现后12个月 | 客户首次承保日 | 首次承保日+12个月-1日 | 包含；满12个月当日不计入 |
| 首现当年度 | 客户首次承保日 | 当年12月31日 | 包含 |

实际观察终点取“自然终点”和“客户清单数据截止日”两者较早者。

完整观察客户：数据截止日已经达到该客户窗口自然终点。

`观察完整率 = 完整观察客户数 ÷ 可追踪新客数`

未满观察窗口的客户仍展示实际已发生业绩，但必须与完整观察客户数量同时看，不能直接用于成熟队列横向比较。

### 7.3 首张保单与再次承保

客户首张保单按以下顺序确定：

1. 承保日期最早；
2. 同一最早承保时间存在多张保单时，投保单号字符排序最小的一张认定为首张；
3. 同日其余保单计为再次承保。

再次承保定义：同一客户除系统首张保单外，在观察窗口内产生的其他保单。再次承保不要求与首张保单产品、业务或机构相同。

| 指标 | 公式/算法 |
|---|---|
| 首张保单可追踪客户 | 当前筛选结果中仍包含系统首张保单的客户数 |
| 再次承保客户 | 观察窗口内至少有1份再次承保保单的客户去重数 |
| 再次承保客户率 | 再次承保客户数÷可追踪新客数 |
| 观察保单数 | 观察窗口内符合筛选的投保单号去重数 |
| 再次承保保单数 | 观察窗口内除系统首张保单外的投保单号去重数 |
| 人均再次承保保单 | 再次承保保单数÷可追踪新客数 |
| 首张期交 | 系统首张保单在当前筛选内的期交保费之和÷10000 |
| 再次承保期交 | 再次承保保单期交保费之和÷10000 |
| 观察期交 | 首张期交+再次承保期交 |
| 再次承保期交占比 | 再次承保期交÷观察期交；分母为0时显示“--” |

产品筛选可能排除系统首张保单，但保留下来的其他产品保单仍按“再次承保”标识。因此在单一产品视图中，首张期交可能为0、再次承保期交不为0，这是正确结果，不代表缺数。

### 7.4 再次承保节奏

M0表示客户首次承保所在自然月；M1表示下一个自然月，依此类推。月份索引按自然月差计算，不按承保后满30天计算。

首现月窗口只展示M0；首现后12个月和首现当年度页面当前统一展示M0—M11，其中首现当年度超过实际年度终点的月份没有业绩。

### 7.5 产品和业务分解

产品名称优先取业绩表产品名称，其次取产品类型、产品代码；均为空时显示“产品待确认”。产品表按观察期交从高到低排序。

分产品和分业务分别展示客户数、保单数、期交、首张贡献、再次承保客户、再次承保保单、再次承保期交和再次承保期交占比。客户跨产品、跨业务购买时，各分项客户数不能直接相加。

## 八、持单深度与购买间隔

持单分析分两步确定范围：

1. 先按所选期间、业务、机构和保单范围找出“期间有业绩且已关联客户清单”的客户；
2. 再查看这些客户在客户清单中的全部已知保单，不限于本期、本业务、本机构或长险。

| 指标 | 公式/算法 |
|---|---|
| 已关联客户 | 第一步选出的投保人id去重数 |
| 已知保单 | 这些客户在客户保单快照中的全部投保单号数 |
| 人均已知保单 | 已知保单数÷已关联客户数 |
| 一客多单客户 | 全部已知保单数≥2的客户数 |
| 一客多单率 | 一客多单客户数÷已关联客户数 |
| 当前有有效保单客户 | 全部已知保单中至少1份当前有效的客户数 |
| 有效客户率 | 当前有有效保单客户数÷已关联客户数 |
| 当前0件有效保单客户 | 已关联客户数-当前有有效保单客户数 |
| 人均当前有效保单 | 这些客户当前有效保单总数÷已关联客户数 |

持单数分档：1份、2份、3份、4份及以上。

当前有效保单数分档：0份、1份、2份、3份及以上。

首次复购间隔：同一客户按“承保日期、投保单号”升序排列，第二张保单承保日期减第一张保单承保日期；至少2张保单且两张承保日期均可解析的客户进入计算。同日多单间隔为0天。

| 指标 | 公式/算法 |
|---|---|
| 首次复购间隔可计算客户 | 满足上述日期条件的客户数 |
| 首次复购间隔中位数 | 可计算客户间隔天数的中位数 |
| 180天内首次复购率 | 首次复购间隔≤180天客户数÷可计算客户数 |

间隔分档：30天内、31—90天、91—180天、181—365天、365天以上。

## 九、保单状态与终止原因

### 9.1 状态归类优先级

同一保单当前状态按以下顺序归入且只归入一类：

1. 保单状态名称=有效：有效；
2. 保单状态名称=停效：停效；
3. 终止原因=退保终止：退保；
4. 终止原因=契撤终止，或犹豫期退保时间非空：犹豫期撤保；
5. 终止原因=到期终止/满期终止：到期/满期；
6. 终止原因=一年期险种逾期未付终止：短险逾期；
7. 终止原因为已配置的理赔、死亡、理赔解约类原因：理赔/身故；
8. 保单状态名称=终止但未命中上述原因：其他终止；
9. 已关联但状态无法识别：状态待确认；
10. 未关联客户快照：未关联。

### 9.2 状态指标

| 指标 | 分子 | 分母 |
|---|---|---|
| 各状态保单数 | 所选期间业绩保单按当前状态去重计数 | 无 |
| 各状态占比 | 对应状态保单数 | 所选期间业绩保单总数 |
| 承保年度有效率 | 该承保年度、当前有效的所选保单数 | 该承保年度所选保单总数 |
| 承保年度退保率 | 该承保年度、当前为退保终止的所选保单数 | 该承保年度所选保单总数 |

承保年度状态表默认展示所选年份向前最多7个年度，仍受业务、机构和长险筛选影响。它用于看不同承保年度保单截至当前快照的状态，不是13个月、25个月或第N保单年度继续率。

终止原因明细按期间业绩保单去重，展示源客户清单中频次最高的12项真实终止原因，不将空值推断为某一原因。

## 十、数据质量指标

| 指标 | 当前含义 |
|---|---|
| 历史业绩明细 | 最近一次成功全量历史导入记录的业绩源行数 |
| 客户源记录 | 最近一次成功全量历史导入记录的客户源行数；不含后续网页增量源行累计 |
| 保单快照 | 当前数据库客户保单快照的实时保单数，包含成功网页增量导入 |
| 源文本异常记录 | 全量历史导入发现的源文本替换字符行数；系统保留原值，不猜测修复 |
| 保单匹配率 | 见第六部分 |
| 保费匹配率 | 见第六部分 |

当前未设置综合“数据质量分”。任何一项匹配缺口、字段冲突或日期异常都应单独看数量和影响范围，不能用一个综合分掩盖问题。

## 十一、客户清单Excel/CSV导入口径

### 11.1 导入范围

客户分析内的“数据导入”只处理客户清单，不处理期交保费等业绩金额。业绩新增或更正仍使用经营看板原有业绩导入口或全量历史导入程序。

### 11.2 必需字段

| 字段 | 是否必需 | 用途 |
|---|---|---|
| 投保单号 | 是 | 保单唯一键、与业绩关联 |
| 投保人id | 是 | 客户唯一键 |
| 导入时间 | 是 | 判断快照新旧、确定数据截止时间 |
| 承保时间 | 是 | 新老客、首张保单、持单间隔 |
| 保单状态名称 | 是 | 当前状态归类 |
| 投保时间 | 否 | 保留业务过程时间 |
| 回销时间 | 否 | 保留业务过程时间 |
| 入账时间 | 否 | 保留最早和最晚入账时间 |
| 犹豫期退保时间 | 否 | 辅助识别犹豫期撤保 |
| 保单终止原因 | 否 | 区分退保、契撤、到期、理赔等 |

支持的常用别名包括“保单号、客户ID/客户id、快照时间、数据导入时间、承保日期、保单状态、终止原因”。字段映射后出现重名时阻断。

### 11.3 文件规则

- 支持`.xlsx`和`.csv`，可一次选择多份；
- CSV支持UTF-8 BOM、UTF-8和GBK/GB18030，推荐UTF-8 BOM；
- Excel在各工作表前20行查找包含必需字段的表头，找到第一张有效明细表后读取；
- 浏览器按8MB分片顺序上传，每个请求均低于Nginx请求体限制；后台任务流式读取CSV/XLSX并使用临时SQLite按保单归并，不设置固定文件大小、文件数和行数上限；
- 实际容量受服务器可用磁盘和后台处理时间约束。上传前应预留源文件、临时归并库、生产SQLite增长和备份所需空间；
- 上传原文件只进入服务器受保护临时目录，不进入Git和日志；预检完成后删除原文件，归并临时库在成功、阻断、失败或24小时未确认后清理；批次只保存文件名、SHA256、大小、行数和汇总结果。

### 11.4 预检与写入规则

1. 预检不写数据库；
2. 批内同一保单多条记录按导入时间最新者作为当前快照，同时保留最早/最晚入账时间；
3. 同一保单在批内对应不同客户，整批阻断；
4. 同一保单与数据库现有客户归属不同，整批阻断；
5. 同一导入时间的承保时间、状态或终止原因冲突，整批阻断；
6. 新文件导入时间早于数据库现值，该保单跳过并明确计数；
7. 新文件导入时间等于数据库现值且关键状态一致，该保单视为不变；
8. 新文件导入时间晚于数据库现值，更新保单快照；
9. 分片全部上传后后台计算文件SHA256；确认导入直接使用该预检任务的受保护归并库，不重新上传原文件；
10. 写入成功后，只重建受影响客户的客户主表，并更新受影响保单及客户的月度事实；
11. 一张新增客户快照如果能关联已有业绩保单，会把该业绩从“未关联”转为已关联；只有客户清单、没有业绩记录的保单不会凭空产生业绩。

## 十二、需要管理确认的口径

请重点核对下表。确认后再决定是否调整页面和算法。

| 编号 | 当前口径 | 可选调整方向 | 影响 |
|---|---|---|---|
| A1 | 新客=当前系统历史首次承保 | 增加“业务新客”：客户首次进入OTO/证保/蚁桥某一业务 | 可区分公司老客向新业务迁移，但不能替代系统新客 |
| A2 | 投保人id作为客户唯一键 | 接入公司统一客户主数据或经过治理的统一客户号 | 会改变客户数、首现时间、持单数和复购率，需全量重建 |
| A3 | 新客首张保单按最早承保时间+最小保单号确定 | 同日多单全部视为首购组合 | 会降低再次承保保单数，尤其影响同日多单客户 |
| A4 | 再次承保包含同日多单 | 只有承保日在首日之后才算再次承保 | 会降低首现月复购，口径更接近日后复购 |
| A5 | 新客率以客户数和期交贡献展示 | 增加新客保单件数占比、年化规保/价值贡献占比 | 需要确认主金额口径和管理用途 |
| A6 | 持单看期间客户的全部已知保单 | 另增“本条线持单”和“所选业务持单” | 可区分全客户关系与本业务经营深度 |
| A7 | 有效=当前状态名称为有效 | 增加“有效且正常缴费”“有效长险”等细分 | 需要缴费状态、应缴/实缴等字段支持 |
| A8 | 退保率=期间业绩保单截至快照的退保状态占比 | 增加年度退保发生率、保费退保率 | 需要退保发生时间和退保金额，当前数据不足 |
| A9 | 首次复购间隔按第一张到第二张 | 增加第二到第三张、最近两次、平均购买间隔 | 可观察持续经营节奏，需新增页面层级 |
| A10 | 观察窗口含未成熟队列并披露完整率 | 默认只看完整队列，未成熟队列另列 | 横向比较更稳健，但当年样本会显著减少 |
| A11 | 产品使用源产品名称/类型 | 建立管理产品分类：年金、增额、保障、个养等 | 便于经营判断，需要正式产品分类表 |
| A12 | 状态是当前快照，不计算继续率 | 接入应缴、实缴、失效/复效发生时间，正式计算13/25月继续率 | 数据到位前不能以当前有效率替代 |

## 十三、建议后续增加的分析维度

以下维度按业务价值排序，尚未纳入当前页面：

1. **业务迁移**：首单业务、第二单业务、跨业务复购路径，重点看OTO、证保、蚁桥之间的客户迁移；
2. **复购层级**：1单、2单、3单、4单及以上客户的保费、有效保单和退保情况；
3. **第N单节奏**：第一到第二、第二到第三、第三到第四张保单的间隔；
4. **成熟队列对比**：仅比较已经走完整个12个月窗口的新客队列；
5. **客户价值分层**：按累计期交、累计价值保费、有效保单数分层，观察客户数量和贡献集中度；
6. **产品组合**：首购产品—复购产品矩阵、同类复购与跨类加保；
7. **机构与业务交叉**：获客机构、复购机构是否一致，识别客户跨机构经营；
8. **品质分层**：新客/老客、多单/单单客户的退保、停效、契撤、到期和理赔状态；
9. **客户经营频次**：年度承保次数、最近一次承保距今天数、连续几年有承保；
10. **继续率**：在补充应缴、实缴和保单年度字段后，正式计算13月、25月继续率及保费继续率。

其中第1—8项大部分可以基于现有数据继续建设；第10项必须等待正式缴费与保全数据，当前不能推算。

## 十四、核对反馈建议格式

为减少往返，可按以下格式反馈：

`口径编号/指标名称 + 保留或调整 + 新定义 + 希望增加的筛选维度 + 是否需要历史重算`

示例：

`A4 再次承保：调整；同日多单全部算首购组合，承保日在首日之后才算再次承保；按业务、机构、产品筛选；历史全量重算。`
