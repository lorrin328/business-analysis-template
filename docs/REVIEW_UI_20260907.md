# UI交互与展示字段审查（2026-09-07）

## 范围与证据边界

本轮审查主看板、客户分析、职拓分析、网点分析、人力趋势与增强分析、市场研判的页面和前端脚本，并按需核对后端返回字段。未读取生产客户明细、未改动远程环境、未实际渲染网页；不对字体、溢出、移动端布局或公网可用性作验收结论。函数复现只使用人为构造的汇总数。方案复核删除不在本报告问题清单内。

结论：已有较完整的单位、口径与权限提示，但筛选状态和实际展示结果仍存在错位。优先修复人力空机构选择、客户跨标签缓存；随后统一失败态并保护市场历史请求顺序。

## 已确认问题

### UI-01 / P1：取消全部机构，人力趋势仍展示全平台数据

- 位置：`js/team-analysis.js:585`、`:586`、`:604`；机构复选框处理位于 `:730`。
- 原因：`hasOrgFilter` 仅在选中机构数大于0且少于全部时成立。全部取消时进入全平台 `teamMock` 分支。同一页面增强分析在 `:170` 将空机构编码为 `orgs=__none__`，两块结果会相互矛盾。
- 复现：提取真实 `getTeamAggregated` 函数，以两个均未选中的机构、平台100人人力/40人举绩/200万元保费调用，实际仍得到人力100、活动率40%，并非空结果。
- 影响：操作者可把全平台结果当成空筛选或某个筛选操作后的结果。
- 建议：无选中机构时明确展示“请选择机构”或返回空数组，并使趋势与增强分析共用选中范围；增加空选、单选、全选三种行为验收。

### UI-02 / P1：新客经营更改筛选后返回概览，会显示旧范围数据

- 位置：`js/customer-analysis.js:392`、`:401`、`:549`、`:562`。
- 路径：先加载概览A；进入“新客经营”；将业务/机构/年份等公共筛选改为B并应用；再回到“经营概览”或“新老客户”。
- 原因：新客经营只更新 `state.cohortData`，旧 `state.data` 仍有效；回到其他标签时，只要 `state.data` 存在便直接 `setOverviewContext()` 和 `render()`，未比较当前筛选键，也未重新请求。
- 影响：顶部筛选为B，KPI与图表为A。截止说明来自A，不能消除使用者按筛选值理解结果的风险。
- 建议：保存每个缓存对应的查询键；返回标签时键不一致就重载，或者公共筛选应用时失效概览缓存。此结论基于完整调用路径静态核对，未浏览器点击复现。

### UI-03 / P2：刷新失败后，旧KPI继续留在新筛选下

- 位置：客户 `js/customer-analysis.js:535`；网点 `js/branch-analysis.js:239`；职拓 `js/zhituo-analysis.js:182`。
- 客户、网点仅替换内容区域和来源文字，没有清空顶部 `kpiGrid`；职拓只修改来源文字，全部旧图表和KPI继续显示。
- 触发：成功加载A，改为B后遇到断网、超时或接口错误。
- 影响：报错文案与旧值并存，截图或只看数字时容易把A误当B。
- 建议：失败时清空或灰化数据区域，显著标记“上次成功结果：A，当前B未加载”；重试成功后解除。保留旧数据时必须同时保留其对应范围。

### UI-04 / P2：市场历史报告可能被晚返回的旧请求覆盖（已修复，待生产验证）

- 本轮修复：报告请求采用递增序号，晚返回的旧报告与旧错误均不再覆盖当前选择；刷新期间发生新的报告选择时，后台刷新不再重新覆盖它。

- 位置：`js/market-analysis.js:489` 至 `:495`，历史选择监听 `:531`。
- 原因：`loadReport` 每次返回均调用 `renderReport`，没有请求序号、当前报告ID校验或取消机制。
- 触发：先选历史A、立即选历史B；A请求较慢，B先返回后A再返回。
- 影响：下拉框显示B，但报告正文是A。客户、网点、职拓已经实现 `loadSequence`，可复用这一模式。
- 建议：仅允许最后一次请求渲染；报告标题旁永久展示报告时间与ID。静态路径确认，未注入浏览器网络延迟。

### UI-05 / P2：市场刷新按钮会丢失当前历史选择（已修复，待生产验证）

- 本轮修复：历史列表返回后保存当时的选择并恢复；不在最近36期内的已选报告保留其选项，避免把分页缺失误当删除。列表请求也增加序号保护。

- 位置：`js/market-analysis.js:476`、`:479`、`:504`。
- 原因：`refreshAll()` 调用 `loadHistory()` 清空重建下拉，默认选项恢复为“最新一期”，再读取下拉值加载报告。
- 影响：查看历史报告时点击刷新，悄然切换到最新一期，妨碍前后比较。
- 建议：刷新开始前保存选中的报告ID，重建选项后恢复；若历史条目已不可用，明确提示并回退到最新一期。

### UI-06 / P2：市场“尚无观察样本”被显示为0%成功率（已修复，待生产验证）

- 本轮修复：null、undefined与空字符串显示“待积累”，真实数值0仍显示0%。

- 位置：`js/market-analysis.js:60`，调用位于 `:136`、`:138`；后端 `backend/market_analysis/insights.py:292`、`:294`。
- 证据：后端无成功观察周期时明确返回 `None`；前端 `formatPercent` 使用 `Number(value)`，`null` 转为0。
- 函数复现结果：`formatPercent(null)`为“0%”；`formatPercent(undefined)`才为“待积累”。
- 影响：尚未形成样本被误读为研究质量或成功率为零。
- 建议：首先判断 `value == null` 或空字符串，再做数值转换；保留真实0%与无样本两种显示。

### UI-07 / P2：网点标题写死数量，可能与当前参考表及筛选矛盾

- 位置：`js/branch-analysis.js:144`（147个常规网点）、`:96`/`:158`（86个转介绍网点）。
- 后端真实规模来自 `backend/branch_analysis/analyzer.py:389`、`:394`，分别为 `len(regular)` 和 `len(referral)`；上方KPI和列表工具栏也已经读取动态数量。
- 影响：更换参考表后，上方实际网点数与固定标题不同；带机构权限或其他范围时尤其容易误解。
- 建议：标题改为“常规网点经营明细”；需要规模时用返回的 `regularStock`、`referralStockExcluded`，并区分名单总量与当前筛选行数。

- 主看板已经限制正式目标缺失时的达成率显示，且生产接口失败不会简单回退展示开发种子数据（`js/kpi-cards.js:17`、`js/data-integration.js:116`附近）。不应将变量名含“Mock”直接判定为使用虚假生产数据。
