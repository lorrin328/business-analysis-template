# 市场研判公众号证据与效率优化方案

## 结论

本次优化不把“公众号数量”当作质量目标，而把“公开可复核的一手信息增量”纳入原有证据体系。完整链路调整为：

`Flash来源侦察 → 程序并发核验 → Pro综合主研 → 程序质量门禁 → Flash定向修复 → Pro升级`

这一组合同时服务四个目标：扩大搜索覆盖、减少Pro在坏链接上的消耗、提高首次成稿成功率、保持公众号证据与官网证据相同的可复核标准。

## 公众号证据合同

公众号原文按B级一手来源管理，必须同时满足：

1. URL为公开直达的`https://mp.weixin.qq.com/s...`文章，不是搜索页、账号主页、短链或转载页；
2. 页面无需登录、Cookie、扫码、验证码或访问控制绕过即可取得正文；
3. 页面可提取真实文章标题和公众号主体，主体与报告声明的发布者一致；
4. 证据摘录是正文中不超过50字的逐字片段，事实中的数字、方向、否定和政策状态可在片段中找到；
5. 独立验证记录最终URL、HTTP状态、复核时间、内容类型、正文哈希、标题匹配和主体匹配结果。

无法满足时只保留为发现线索。若同一机构官网存在同内容镜像，使用官网页面并按`official`、`company`或`association`的实际类型归档；没有镜像时披露缺口，不补造来源。

## 效率与性价比

- Flash承担广覆盖发现，目标为至少12组检索主题和18—24项候选，并定向尝试监管、协会和寿险公司公众号。
- 候选进入Pro前由程序并发核验，默认4个工作线程、最多8个；不可达、正文缺失、敏感查询参数、非公网地址、标题/主体/摘录不符的候选提前淘汰。
- Pro获得的是短证据包而非未经筛选的搜索结果，主要资源用于宏观、监管、同业和条线影响的综合判断及历史滚动。
- 确定性计数、来源校验、历史关系、变化信号和质量评分继续由程序处理，不花模型预算。
- Flash侦察失败时自动降级到Pro原流程；侦察是提效层，不是新的单点故障。

## 可靠性门禁

- 最终报告仍逐条重新访问全部外部来源；前置核验不能替代发布前终检。
- 公众号主体或标题未通过时直接阻止该来源发布，不能由模型改标。
- 最低9.0分质量门槛、宏观和监管A级证据、同业一手证据、历史连续性及行动闭环要求全部保留。
- 研究失败继续保留上一期有效报告；只读侦察测试不写`latest.json`、报告归档或`status.json`。

## 观察指标

连续六期记录：

- Flash侦察候选数、程序通过数、淘汰原因；
- 公众号候选数和经主体核验的有效数；
- Pro首次成稿通过率、Flash修复率、Pro升级率；
- 完整运行时长、模型调用相对成本、外部来源最终验证率；
- 每个同业模块的一手来源覆盖率；
- 报告质量得分及人工抽检结果。

目标不是强求每期出现公众号，而是在不降低证据门槛的前提下，提高新动作发现率，并把完整运行时间和Pro升级率逐步压低。

## 验收边界

- 专项测试覆盖模型路由、侦察证据注入、侦察失败降级、只读测试不发布、公众号主体匹配与错误主体拒绝。
- `wechat-official-source-research`和`life-insurance-market-research`均通过Skill结构校验。
- 生产部署后先执行`--source-scout-only`，确认历史报告和运行状态哈希不变，再等待下一次完整三天周期验证综合效果。
