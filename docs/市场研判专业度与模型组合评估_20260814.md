# 寿险市场研判专业度与模型组合评估

## 一、结论

截至2026年8月14日，该模块已经具备“可用于管理层日常研判”的专业基础，综合成熟度评估为 **7.6/10**。它的优势不是文章写得长，而是形成了“多源检索—事实与判断分层—历史主题续接—独立来源复核—失败不覆盖上一期”的闭环；当前主要短板是首次发布成功率、微信公众号覆盖、分析字段的事实纪律、行动重复度和模型调用可观测性。

模型不宜二选一。正式生产采用：

- **DeepSeek V4 Pro**：承担首次深度研究、跨期综合、监管与同业含义辨析、条线影响和最终报告主稿；
- **DeepSeek V4 Flash**：承担Claude Code轻量子任务、检索摘要和第一次定向修复；
- **DeepSeek V4 Pro升级修复**：Flash修复后仍未通过时再启用，最多一次；
- **确定性程序**：继续负责来源计数、字段长度、历史元数据、变化信号、坏源安全剔除和独立证据验证，不交给任何模型自由判断。

这套组合保留Pro对复杂研判的上限，同时把规则明确、失败可验证的工作交给Flash。DeepSeek官方当前定价中，Flash的缓存未命中输入和输出价格均约为Pro的三分之一；两者均支持1M上下文、JSON和工具调用。价格与能力以[DeepSeek官方模型与价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)及[Claude Code接入说明](https://api-docs.deepseek.com/quick_start/agent_integrations/claude_code/)为准。

## 二、真实运行审计

审计范围为2026年7月22日至8月14日已发布的8期报告。

| 维度 | 已核验表现 | 判断 |
|---|---|---|
| 报告结构 | 每期11—15个原子模块，四层均有覆盖 | 结构清晰，优于长篇堆砌 |
| 证据覆盖 | 每期13—26项来源；最新一期14项来源中8项为官方来源 | 官方证据占比提升明显 |
| 历史续接 | 最近各期持续/强化主题5—10项，新增主题2—5项 | 已形成滚动研究而非全文复制 |
| 发布门禁 | 无法核验的来源阻止发布；坏源只有在证据仍满足门槛时才剔除 | 事实安全边界较强 |
| 运行时长 | 最近成功运行约19—25分钟 | 符合深度研究任务特征 |
| 首次成功率 | 8月5日和8月14日均因单一/少量坏链接在systemd重试后发布；最近4个周期首次成功2次 | 可靠性仍有提升空间 |
| 渠道覆盖 | 微信公众号可独立验证来源始终为0项，报告已披露限制 | 没有伪造，但渠道覆盖仍不足 |
| 变化识别 | 已出现持续、强化和新增；尚未出现反转或失效 | 不应强行制造变化，但需持续观察分类灵敏度 |

## 三、专业度分项评价

| 专业维度 | 评分 | 主要依据 | 改进重点 |
|---|---:|---|---|
| 事实与证据 | 8.5 | 官方证据、正文摘录、内容哈希、URL和发布时间独立复核 | 提高一手公司/公众号可达率 |
| 模块化表达 | 8.5 | 一个模块回答一个问题，事实、判断、影响和失效条件分栏 | 控制标题和摘要中的数字堆叠 |
| 跨期迭代 | 7.5 | 稳定topicKey、previousReportId和变化状态 | 识别真正反转/失效，减少长期机械持续 |
| 条线转化 | 7.5 | 已落实到经代、OTO、证保、蚁桥、社保商办及责任人 | 减少连续多期重复动作，增加验收结果回写 |
| 运行可靠性 | 6.5 | 失败保留上一期、检查点可恢复 | 坏源在同一进程内快速修复，减少整轮重启 |
| 成本与可观测性 | 6.5 | 有调用预算和运行日志 | 记录每次主研/修复模型、耗时、轮次和CLI估算成本 |

该模块适合作为管理层的持续决策输入，但仍属于“机器校验研判”，不能替代监管合规部门、投资部门或业务条线对重大决策的人工签审。

## 四、模型组合与升级规则

| 阶段 | 默认模型 | 原因 | 失败处理 |
|---|---|---|---|
| 首次深度研究 | V4 Pro `[1m]` | 需要读取历史、内部快照，完成多轮搜索、跨期判断和条线综合 | 结构和来源门禁校验 |
| Claude轻量任务/检索摘要 | V4 Flash | 官方建议Haiku/子代理映射到Flash；简单Agent任务能力接近Pro | 不直接决定发布 |
| 第一次定向修复 | V4 Flash | 错误边界明确，通常是坏链接、证据替换或格式关系；修复后仍须完整验证 | 未通过则升级Pro |
| 第二次升级修复 | V4 Pro `[1m]` | 处理Flash未解决的证据冲突、复杂同业替换和历史关系 | 仍失败则停止发布，保留上一期 |
| 计数、历史关系、变化信号、来源验证 | Python确定性程序 | 规则可计算，不应消耗模型或允许模型漂移 | 硬门禁失败 |

若一次运行无需模型修复，仍只有Pro主研调用；若需要一次修复，则修复部分的单位token价格理论上降低约三分之二。总费用下降幅度取决于WebSearch、输入缓存、输出长度和修复占比，不以CLI显示的美元估算值代替DeepSeek实际账单。

## 五、本次改进

1. 新增主研、Flash修复、Pro升级三段式模型路由，并兼容原`MARKET_ANALYSIS_MODEL`配置。
2. 单一坏源无法安全剔除时，不再立即退出等待systemd重启；同一进程内先用Flash进行定向修复，失败再升级Pro。
3. 状态文件记录模型计划及每次调用的角色、模型、耗时、轮次、token、WebSearch次数和CLI估算成本；不记录提示词、密钥或网页正文。
4. 报告页面展示“Pro主研 / Flash修复 / Pro升级”的模型组合，避免用户误以为全程只使用一个模型。
5. 提示词进一步限制：判断和影响不得引入证据中不存在的新数字、日期、政策状态或公司动作；量化预测必须标为推演并设置失效条件。

## 六、后续六期观察指标

- 首次发布成功率不低于80%；
- 发布报告的外部来源独立验证通过率保持100%；
- 宏观、监管官方A级证据覆盖率保持100%，同业一手A/B证据覆盖率保持100%；
- 单期官方来源占比原则上不低于40%，不足时必须披露原因；
- 单期完整运行中位时长控制在30分钟以内；
- Flash首次修复成功率、Pro升级次数和模型调用结构可从`status.json`审计；
- 微信公众号来源仍为0时继续如实披露，不以转载冒充官方微信；
- 连续三期重复的条线行动必须显示进度、结果或调整原因，不能只重复提出同一要求。
