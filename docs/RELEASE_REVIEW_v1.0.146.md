# v1.0.146 发布与复核记录

状态：代码已同步PR #24，候选与Linux镜像验收中，尚未据此宣布上线。

本次处理日常导入造成历史字段损失、客户事实未随源数据更新、卡片与详情/Excel口径分离、审计失败仍返回成功退出码，以及发布恢复点早于停服造成写入损失的风险。

## 用户可见变化

- 上传区显式选择“完整月替换”或“业绩补充”，预览行数、期间与覆盖范围，再确认写入。改变文件和选项须重新预览。完整月保留原有关键字段要求；补充模式相同记录跳过，差异记录拒绝。
- KPI卡片、详情、AI只读接口和Excel共享指标合同。真实零保留；缺目标、同期、人力或完整覆盖时说明不可计算。活动率同比用百分点，人均按覆盖自然月及月均人力计算。
- 客户事实与原始导入处于同一事务。严格格式编号仅作为候选键，歧义键只精确关联；未确认的客户关系不自动归并。

## 验证与发布门禁

1. 合成数据回归、只读审计行为、导入回滚、前端状态流、Linux真实互斥、镜像运行及依赖漏洞检查。
2. 生产一致性备份构建候选库，验证迁移性能、年度金额勾稽、源表/目标/账号不变。仅两条已知客户迁移时重建客户事实；未知、混合或显式强制迁移仍完整重建，避免本次客户修复重复扫描20年主聚合。
3. 仅从已提交、通过验证的Git归档部署；本机健康与正式公网HTTPS、静态资源哈希、鉴权和业务页面均验收后才接受发布。
4. 停服后冻结备份包含停服前全部已提交写入。新版本启动前失败自动恢复；启动后必须核实新增写入与迁移兼容性，不能直接覆盖数据库。

## 恢复与保留

部署输出恢复包路径及 `accept-release --confirm-review-complete` 命令。只有完成完整复核才执行接受，保留本次冻结数据库、元数据、代码/配置恢复包及旧依赖；清理只针对已验证、受管理的旧备份。独立介质副本不进入仓库和镜像。

操作人员需先确认服务停止、数据库写入边界和恢复材料校验，再按部署输出的自包含恢复工具处理。不能使用在线准备阶段的较早备份替代停服冻结点。

## 剩余边界

- 继续率缺少应缴实缴与观察点源，不增加推算数值。
- 经代价值沿用既有暂计零业务口径，明确标注来源未接入；不把暂计值当成完整价值结果。
- 历史凭据轮换需要对应平台的吊销证明，本轮代码修复不能代替轮换。
- 同步目录历史冲突保留待逐项核对，后续开发采用同步目录外的Git工作区；不批量删除冲突副本。
- 经营督导工作台作为后续产品迭代，责任归属、正式目标和验收规则需沿用正式来源。
