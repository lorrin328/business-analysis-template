# 机构维度连续挂零指标需求报告

状态：已确认，实施验收中
编制日期：2026年8月31日
用途：明确业务口径、页面位置、数据条件及开发验收要求。
核验范围：本地现有页面、计算代码和数据库字段；未连接生产环境，未计算各机构实际挂零天数。

## 2026年8月31日实施确认

用户已确认采用**期交保费**判断，日期采用**业绩归属日**，并授权同步GitHub、部署Ubuntu。项目沿用OTO、证保、蚁桥；跨月连续，只有犹退无承保计挂零。下文为原始需求分析，涉及保费与日期的备选项已由本条确认替代。

实施规则：源表期交保费>0且承保件数>0作为正常新增承保证据；期交正数但件数非正或缺失标为待核，不用净保费或净件数判断。当日明确承保即可显示0天。业务日期全表优先年月日，仅在不存在该列时使用入账时间，绝不回退承保日。日期只有月精度时保留异常，不补成月初。

当前没有独立的正式项目开展登记及完整截止确认字段。本期根据截至日已出现的本年业绩、已开始期间的正目标及人力记录确定观察对象；未出现组合显示—而不认定挂零，已停办项目不自动剔除。数据范围依据现有按月替换的业绩源，整月缺失不跨越，最早可观察日之前不补零；无法证明完整历史时显示≥N或—。指标保守截止到全体转型业绩最近日期与昨日的较早日期，不延伸到未导入日期，也不能声称最近出单日等于来源正式完整截止日。

新增独立agg_org_daily_activity表及20260831_org_zero_streak强制聚合迁移。导入前只读检查日期列结构，导入完成后从实际持久化业绩明细分块刷新新表，确保全量、增量、原始SQLite重建一致；既有净额指标保持原口径。此举会增加业绩导入耗时，网页查询仅访问汇总表。正式开展清单及来源完整截止字段仍为后续完善项。

## 一、以当日新增承保判断挂零，避免犹退抵扣造成误判

拟在经营分析看板“机构维度”中新增“连续挂零”指标，按机构及其项目分别识别截至统计日连续没有新增承保保费的自然日数，供日常经营督导使用。

用户已明确：一个自然日新增保费为0，计为挂零；当天同时有承保和犹退，即使承保保费小于犹退金额，当天也不应计为挂零。因此，计算必须保留承保正向发生情况，不能直接使用日净保费是否等于0或小于等于0来判断。

本报告建议采用以下定义：在已开展且数据完整的机构、项目范围内，当天没有产生正向新增承保保费，记为挂零1天；存在正向新增承保保费，当天不挂零，连续挂零天数归0。犹退和其他负向冲销继续影响现有净保费指标，不抵消本指标对当日新增承保的识别。

只有犹退、没有新增承保的日期，建议计为挂零。这是根据管理目的提出的补充规则，尚不作为用户已确认口径。

## 二、放在机构表格最后，保留机构和项目两层观察

现有机构维度依次展示期交保费、价值保费、长险期交、10年期产品、商保年金、保障类产品。新增“连续挂零”分组放在“保障类产品”之后，作为表格最右侧的最后一组指标，不新增一级菜单，不改变现有指标顺序。

本期建议沿用现有项目层级，将“项目”解释为页面中的业务模式，即OTO、证保、蚁桥。现有机构范围为上海、湖北、四川、辽宁、山东、广东、福建、浙江、河南、北京。经代和职拓不在当前机构表格项目列表中，不在本次默认扩展范围；若项目另指具体合作项目或网点，需在开发前调整维度映射。

建议只增加一个主列“连续挂零（天）”，控制表格宽度。点击数字或查看提示时，再展示挂零起始日、最近一次新增承保日、实际统计截止日及计算说明。

| 显示位置 | 展示规则 |
|---|---|
| 展开的项目行 | 显示该机构、该项目的连续挂零天数 |
| 收起时的机构汇总行、展开时的机构小计行 | 按该机构所纳入项目的每日承保情况重新计算；当天任一项目有新增承保，机构整体即不挂零 |
| 表格底部合计行 | 建议显示“—”，避免把不同机构的天数相加；如后续需要整体挂零指标，应单独按每日承保情况重算 |
| 未开展的项目 | 显示“未开展”或不纳入考核，不能显示挂零 |
| 数据不足或日期精度不足 | 显示“—”及原因，不能默认填0 |

机构汇总天数不能取各项目天数的合计、平均值或最大值。例如OTO当日有承保、证保已连续3天无承保，则机构整体为0天，证保项目仍为3天。

现有页面会过滤本期及同期相关指标全部为0的项目行。该逻辑需为本指标调整：已开展但没有业绩的项目必须能够显示；不得仅从有业绩的记录反推项目名单，也不得将全部机构与全部项目的组合一律认定为已开展。实施时需明确项目开展范围及生效日期的权威来源，缺失时标为“开展状态待确认”。

## 三、先判断每日状态，再计算截至日连续天数

设机构为i、项目为p、业务日期为d，G(i,p,d)为当天经核验的新增承保正向保费合计，金额使用选定保费字段的原始精度。先识别新增承保事件，再汇总正向金额；不能把所有正金额调整记录都自动视为新增承保。

- 已开展、数据完整且G>0：当日不挂零，连续天数为0。
- 已开展、数据完整且G=0：当日挂零，连续天数在前一自然日基础上加1。
- 开展状态、来源覆盖或交易性质无法确认：状态为待核，不能当作挂零或正常承保。

公式为：当G(i,p,d)>0时，C(i,p,d)=0；当G(i,p,d)=0且前一天结果可确定时，C(i,p,d)=C(i,p,d−1)+1。该递推仅在连续、完整的数据覆盖范围内成立。

如果截至日为D，最近一次新增承保日为L，且L到D间数据完整，则连续挂零天数为D−L。例如8月28日有新增承保，8月29日至31日均无新增承保，截至8月31日为3天；8月31日重新承保后为0天。该例仅用于说明规则，不代表当前实际数据截止日。

计算需补齐日历上的每一个自然日，周末、节假日均计入；跨月、跨季度及跨年不自动清零。跨期连续性是本报告建议，实施时以可验证历史为限。

如自项目开展日S起即有完整数据且从未承保，则截至D计为D−S+1天。如果只能确认某段历史连续无承保，但更早数据缺失，应显示“至少N天”，并说明可追溯起日；若中间出现未知日期，不得跨过缺口拼接成精确连续天数。

## 四、按完整业务日计算，防止把未导入日期算成挂零

本指标展示的是“截至某日的连续状态”，不是某个月或某个季度挂零天数之和。年度、季度、月度和自定义区间筛选用于确定观察截止日，回溯连续天数时允许读取区间开始之前的完整历史。

月份复选时，以所选月份中最晚的有效日期作为观察截止日，回溯时仍检查真实连续日历。不能将不相邻月份拼接计算，也不能按月份相加。页面必须在指标提示中展示实际截止日，避免用户将其误读为所选期间累计挂零天数。

建议默认截至北京时间前一个自然日，并且不得晚于数据源已确认完整覆盖的业务日期。当天尚未结束时，不将当天无出单直接记入正式连续天数；当天承保情况如需展示，可另作临时状态提示。

需分别维护“数据完整覆盖至哪一天”和“最近出单在哪一天”。当前代码主要从日聚合表的最大业务日期推定数据截止；这种方式无法证明最后几天全体无出单时的数据完整性。新增指标不能直接把各机构或各项目的最后出单日当作各自截止日，否则长期未出单的对象将无法正确累加。

完整覆盖范围内无业务记录的日期可以补为零；来源漏传、上传失败、整日覆盖未经确认、只有月数据的日期不能补零。不同来源需要合并计算机构整体时，应使用共同完整截止日；并列显示不同截止时应逐项说明，不直接作同日排序比较。

## 五、承保、犹退及特殊记录的判断示例

下表金额单位为万元，均为规则示例，不是实际经营数据。“新增承保保费”指选定保费口径下的正向发生额，未与退保轧差。

| 当天情况 | 新增承保保费 | 犹退或冲销金额 | 日净保费 | 是否挂零 | 连续天数处理 |
|---|---:|---:|---:|---|---|
| 无承保、无犹退，且数据完整 | 0 | 0 | 0 | 是 | 前一天加1 |
| 有承保，无犹退 | 2 | 0 | 2 | 否 | 归0 |
| 承保小于犹退 | 2 | 3 | -1 | 否 | 归0 |
| 承保恰好被犹退抵消 | 2 | 2 | 0 | 否 | 归0 |
| 承保大于犹退 | 3 | 2 | 1 | 否 | 归0 |
| 只有犹退，没有新增承保 | 0 | 2 | -2 | 建议为是 | 前一天加1 |
| 存在件数记录，但所选口径新增保费为0 | 0 | 0 | 0 | 是，前提是记录含义已确认 | 不以件数替代保费条件 |
| 只有正向保费调整，没有真实新增承保 | 非新增承保 | 0 | 正数 | 建议为是 | 先核验交易性质 |
| 数据尚未完整导入 | 不确定 | 不确定 | 不确定 | 不可判断 | 显示“—” |

同一天先承保后犹退：如果确实发生真实新增承保，建议当天仍不挂零；如果是重复导入、误录冲正或无效交易，不应凭正向记录认定出单。后续犹退原则上也不追溯抹去真实发生过的承保日；来源纠错则应重新计算受影响日期及其后续连续天数。

不能用净承保件数判断是否出单。两笔记录分别为承保和犹退时，件数也可能轧差为0。保单去重用于避免重复导入或同单重复行，但不能在去重时先将承保与犹退净额合并，导致正向承保事件消失。

金额是否为0应在原始金额精度上判断，不使用显示为万元且四舍五入后的数值。缺失金额、无效日期或性质冲突应进入异常状态，不能通过补0消除问题。

## 六、现有数据具备字段基础，但还不能直接按净额实现

本地原始业绩表performance已核验包含销售机构名称、业务模式、投保单号、年月日、承保时间、入账时间、期交保费、年化规保及承保件数等字段。现有agg_org_daily_performance按机构、业务模式和日汇总期交、规保等净额，没有独立保存新增承保发生额或出单标志。

本次只核验了字段结构，没有读取客户或保单明细，也没有验证正负记录的实际分布。因此，字段存在不等于已经证明所有历史记录足以还原承保事件。原始业绩表未见专门的犹退或交易类型字段；实施前仍需核验承保件数、金额方向、同单多行及日期的关系，必要时补充来源字段，不能仅凭正负号完成所有交易分类。

建议新增独立的机构项目日承保汇总，或对现有机构日表扩展独立字段，至少能够提供业务日期、机构、项目、当天新增承保正向发生额及新增承保标志。数据完整范围、项目开展日期和判定异常另行保留。保单号等识别字段在后端处理，不向页面返回敏感明细。

正式请求从日汇总计算连续天数，避免每次页面加载扫描全部保单。对没有记录的已开展项目，通过有效项目名单和完整日历参与计算。全量导入、增量导入、同月重导和历史重建均需应用相同口径，相关缓存随导入刷新。

如实施涉及聚合结构或逻辑变化，应按项目规则新增唯一迁移版本并标记requires_aggregate_rebuild=1，从保留的原始明细生成新汇总，不用服务器旧Excel覆盖现有生产数据。页面和接口沿用机构模块权限，并对新字段明确使用“天”作为单位，不能沿用接口整体的“万元”说明。

现有期交、价值、长险期交及各产品保费指标继续按原规则计算；本次增加出单连续性观察，不修改既有净保费业绩结果。

## 七、开发前需锁定的口径及建议

用户已经明确了新增保费为0的挂零条件、承保不受犹退轧差影响，以及模块位于机构维度所有指标之后。下列细节尚未明确，本报告先给出建议，不能直接视为最终业务决定。

| 事项 | 本报告建议 | 对结果的影响 |
|---|---|---|
| 保费字段及业务范围 | 按“是否有新增承保”管理目的，优先考虑原始年化规保正向发生额，覆盖期交与趸交；若仅考核期交，改用期交保费并将列名明确为“期交连续挂零” | 仅有趸交或短险出单的日期，两个口径可能得到不同结果；不能默默套用期交或长险过滤 |
| 日期归属 | 优先沿用业绩源明确的年月日业务口径；当前机构日表优先读取年月日，其次读取入账时间等候选字段 | 若要求按实际核保通过日督导，需改按承保时间，结果可能不同于现有业绩日表；不能逐行任意混用日期 |
| 项目含义及开展范围 | 项目沿用OTO、证保、蚁桥，依据正式开展名单及生效日期纳入 | 未开展、已停办及状态不明的组合不能机械累积挂零 |
| 连续周期及只有犹退的日期 | 自然日连续，跨月不清零；只有犹退无新增承保计挂零 | 反映持续未出单状态，不等同月内累计挂零天数 |

这些口径应由业务管理方在实施前确定，开发方负责验证字段能否支撑并落实计算；数据维护方负责确认来源完整覆盖日期及项目开展范围。未解决的数据条件在界面中明确标识，不先以0上线。

## 八、验收以边界结果和既有指标不变为准

后续实施验收至少覆盖：

1. 有承保且净保费为负、为零或为正，均不挂零；只有犹退按确认口径处理。
2. 连续多日无承保、恢复承保、跨月、跨年、周末及节假日计数正确；显示值与日期差一致。
3. 无数据日期仅在来源完整时补零；未开展项目、未完整导入日期和缺少日精度的历史不误判。
4. 从未出单但已开展的项目能够显示；历史不足时展示下界或不可计算状态，不伪造完整天数。
5. 机构小计重新按每日出单计算，不能相加或取最大值；不同截止的机构不作无提示的横向比较。
6. 期间切换、月份复选、全局截止、展开收起和机构筛选后，指标位置及实际截止说明保持正确；不将月份天数相加。
7. 重复导入不重复识别承保，历史修正能更新后续连续天数；正向调整与真实新增承保完成区分。
8. 新指标位于保障类产品之后，现有保费、达成率和同比结果不变，机构权限及其他模块行为不受影响。
