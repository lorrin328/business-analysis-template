# 日常Excel字段保存与API读取核验

核验日期：2026-09-12。范围为本地 `excel/原每日导入` 四份实际源表、当前导入代码和 `backend/business_data.db`，未核验生产库，未执行导入或部署。

## 核验结论

四类日常表解析出的全部命名业务字段在当前本地SQLite原始表均存在，没有发现缺失列。但最新源文件与本地数据库行数不同，不能据此声称最新Excel已经完整入库，也不能把字段覆盖核验等同于逐单元格内容一致。

源文件为业绩 `AI-经营分析业绩基表_20260912_20081141.xlsx`、经代 `经代业绩分析 (47).xlsx`、人力 `N1AI-人力基表_20260912_20075793.xlsx`、价值 `AI-经营分析价值基表_20260912_20080512.xlsx`。经代解析时剔除1行尾部合计，其第二工作表为过滤条件说明，不进入明细表；其他三份各有一个工作表。

## 代码证据与范围

- `backend/etl/columns.py`：识别首表表头、读取所有列、清理列名和无名称列。
- `backend/etl/parser.py`：四类表均复用上述读取逻辑，经代单独剔除明确尾部合计。
- `backend/services/excel_pipeline.py`：解析结果保存在 `raw_tables`，另行生成汇总。
- `backend/services/import_safety.py`：`append_raw_frame` 写入所有解析列，自动补充新增列；缺失列写NULL。`replace_months` 按覆盖月份替换，非历次上传归档。
- `backend/customer_analysis/importer.py`、`backend/history_import/importer.py`：其他导入存在归并或固定字段映射，本轮未扩展其API。

Excel公式表达式、格式、额外工作表等不在保存范围；解析类型转换也使得此流程不是逐单元格原样存档。业务字段覆盖与原文件无损保存应区分。

## 本地候选改动

新增四类日常原始表字段目录与分页明细接口，默认全部列、全部期间，可选择列并按原始字段精确筛选。保留原有汇总接口。新增独立 `ai_raw_data` 权限，管理员默认允许，高级和普通账号默认拒绝，支持管理员授权；旧汇总专用Token不自动扩大读取范围。新增只读查询和访问审计，无业务表结构及聚合口径修改，不要求重建数据库。

接口使用说明见 `AI只读接口说明.md`。当前变更尚未发布到GitHub或Ubuntu。

## 验证结果

- 新增明细、原AI只读、账号权限、权限修改回归、荣誉权限、前端静态、API契约和导入安全相关测试共 **201 passed**；另有1条既有Starlette/httpx弃用警告。
- 通过SQLite Online Backup创建本地验证副本，使用实际FastAPI路由按每页1000行读取四表：业绩41页、经代138页、人力22页、价值2页，共203页、200,139行。将每行所有字段序列化后，与同副本独立SQL读取的全量内容逐表进行有序SHA256比较，行数及内容全部一致。
- 真实数据副本核对仅为避免创建真实账号而替换了认证依赖和审计写入；真实Basic、会话、独立权限、管理员授权、旧Token拒绝及审计脱敏均由隔离测试库覆盖。真实数据不输出到报告。
- 验证副本 `PRAGMA main.quick_check=ok`；JavaScript语法及 `git diff --check` 通过。新增权限界面脚本的内容哈希已同步更新，未进行浏览器交互验收。
- 筛选值放入ASCII转义JSON请求头 `X-AI-Filters`，避免进入URL及常规代理访问日志；操作审计不保存筛选值和原始明细。
- 本轮不重建或导入业务数据，不改变聚合逻辑，无生产访问及上线验收。分页有已落库日常导入ID检查，离线重建/手工修改/数据库切换仍需在批量读取时避免，不能称为跨请求冻结快照。
