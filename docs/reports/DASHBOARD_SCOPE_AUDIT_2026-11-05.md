# 主经营看板统计口径排查与修复

日期：2026-11-05。修复版本：v1.0.170。状态：本地修复并验证，用户已授权同步GitHub和部署Ubuntu；最终发布结果另记发布验收。

## 结论

用户截图中的问题属实。此前业务平台趋势刻意独立于顶部统计范围，前端只请求年份，后端趋势接口也仅支持年初至截止日，不能表达单日或自定义起点。因此顶部换范围后，趋势仍显示其他月份、上年仍可能显示完整年度。旧规则已由本次范围合同替代。

本次覆盖主看板KPI、机构、业务平台、产品、交期、队伍及Excel导出。已修复范围与筛选链路中发现的确定问题；不将所有指标宣称为相同时间精度。人力和价值仍为月级，队伍独立展示其年/季/月期间。

## 发现及处理

| 项目 | 原有问题 | 修复后行为 |
|---|---|---|
| 趋势起止 | 全局范围没有传到趋势；只有截至参数也无法表达区间起点 | 两个趋势接口支持rangeType/startDate/endDate；年度累计、月度、单日、自定义均接入；局部月份与顶部范围取交集 |
| 累计及同期 | 累计从年初、上年完整期间、混合来源又缩到最早出单日，可能与KPI不一致 | 从所选起点累计；上年映射同月同日；显式范围按各来源实际记录合计，不再额外丢弃较新来源；上年覆盖不足披露实际期间 |
| 日曲线 | 闰年后按数组位置比较会日期错位，缺日源可能产生局部伪累计 | 按月日标签对齐，闰日按年度自然日处理；无日明细的月份不伪造日线，回退也不延长至上年实际覆盖之外 |
| 机构筛选 | 趋势及队伍全部取消机构可能回到全国；缺机构明细可能回退总额 | 转型部分按所选机构计算，空选不回到全国；经代无同一机构维度，仍独立全国/销售平台并明确提示 |
| 机构表控件 | 取消“全部”后可见勾选与实际计算仍为全部 | 保持该表原有至少一个范围的规则，“全部”按钮与勾选状态一致 |
| 经代销售平台 | 销售平台原始日行未受全局范围约束 | 平台行按起止过滤；部分月无日期的历史平台金额不冒充可核算日实绩；保留平台明细覆盖限制提示 |
| 交期筛选 | 清空业务、渠道或平台后，空参数被后端解释为全部 | 空选择显式传__none__，与全部区分；全局切年同步交期控件年份 |
| 交期精度 | 全年任意日数据触发整体日源，可能漏掉另一月源；部分月缺日数据可能读入整月 | 按业务来源及月份选择日/月数据，完整自然月可用月源；部分月无日源的金额、件数、件均不可算，返回NULL和范围告警 |
| 异步刷新 | 旧交期请求及旧失败可能覆盖新结果；缓存未充分区分日期 | 加请求序号、范围缓存及代际保护；当前读取失败时清空对应旧结果并提示，不以旧数冒充新筛选 |
| 零、负数、缺失 | 以最后正保费月判断月份；产品零保费结果清掉有效件数；缺人力或零分母可能算作0 | 有效零与负向冲正保留；产品保费和件数独立保留；人力边界缺失留空，零分母比率不可计算 |
| 舍入 | 产品分类各自四舍五入后再相加，与KPI有小额尾差 | 产品、交期新增premiumTotal，未逐类舍入先汇总，再保留两位小数；分类展示值保持兼容，并解释尾差 |
| Excel | 平台趋势仍导出完整年背景 | 平台趋势遵守所选范围；队伍另读完整月度背景，导出说明区分两者 |
| 可读性 | 趋势左右轴标签及单位有裁切风险 | 图表留出轴标签和单位空间；范围内部分月金额标为“期内月度” |

仅修改读取与展示合同，没有改写Excel原件、既有历史记录、持久聚合公式或数据库结构，不需要聚合重建。经代2020—2024历史净件数与2025年起投保单号范围去重合同不变。市场研判及自动部署均未启用。
